# GHCR autenticado no finance-e2e

O run 40935705701 do PR #91 e o run 40935604538 da `main` falharam antes dos testes: o pull do PostgreSQL oficial retornou `rate_limit` no GHCR e no ECR em todas as tentativas. O PR #93 adicionou backoff, mas o run da `main` prova que retries não eliminam a causa.

O job `finance-e2e` usa o `GITHUB_TOKEN` efêmero do próprio workflow com `packages: read` e `contents: read` apenas nesse job. O login vai por stdin ao Docker, sem PAT nem registro de valor em log. A aquisição continua em `scripts/homolog/finance/images.mjs`: versões e digests OCI oficiais fixos, GHCR primeiro, ECR com o mesmo digest como fallback, inspeção do digest baixado e execução pelo ID imutável da configuração. Falha de autenticação, TLS ou integridade continua fatal. O ambiente de banco continua descartável e os jobs `finance-e2e` e `finance-quality` permanecem obrigatórios.

O run 40940180762 comprovou que o login foi aceito e todos os gates passaram, mas o GHCR ainda retornou `rate_limit` em três das cinco imagens. O ECR forneceu os mesmos digests fixos nessa execução. Logo, autenticação sozinha não encerra a indisponibilidade; o cache OCI verificado do PR seguinte reduz a dependência dos registries em cada runner novo.

O cache do GitHub Actions usa chave exata derivada da lista de imagens fixas e só é salvo depois de adquirir e verificar os cinco índices oficiais. A restauração executa somente IDs de configuração `linux/amd64` fixados a partir do run 40940180762; ausência ou divergência falha, sem pull substituto silencioso. Um cache frio ou expirado ainda depende dos registries oficiais; espelhamento administrado seria necessário se ambos ficarem indisponíveis nesse momento. Espelhar imagem em outro namespace exige conferir índice, plataformas e digest antes de liberar seu uso, sem trocar versão nem origem silenciosamente.

O run frio 40943246662 do PR #95 passou `js`, `sql`, `finance-e2e`, `secrets` e `finance-quality`. O log do `finance-e2e` confirmou os cinco digests e IDs esperados e salvou o cache `finance-oci-v1-Linux-X64-bd2f75ad00ea0a09b8a5f560e21d06753cf6240edb58ec95885fcc588337ef30` (919 MB comprimidos). A próxima execução da mesma branch comprova a restauração; esse teste é necessário porque o primeiro run só verificou a criação do cache.
